## 9. Анализ ошибки из фрагмента кода

**Фрагмент:**
```java
for (int i = 0; i <= hours.length; i++) { total += hours[i]; }
```

**Ошибка:** Выход за границы массива (`ArrayIndexOutOfBoundsException`). 
Индексы массива в Java начинаются с 0 и заканчиваются на `length - 1`. Условие `i <= hours.length` позволяет циклу сделать лишнюю итерацию, когда `i` равно длине массива. В этот момент происходит попытка обращения к элементу, которого не существует.

**Исправленный подход:**
```java
for (int i = 0; i < hours.length; i++) { total += hours[i]; }
```

## 11. Собственные формулировки

**Где находится цикл обработки массива?**
В Activity-диаграмме цикл скрыт внутри блока **A1 (Преобразовать и проверить каждый элемент)**. В коде цикл реализован внутри метода `parseHours` (цикл `for` от 0 до 4) для проверки каждого числа, а также в методах `total`, `average`, `overtimeDays`, `weeklyOvertime` (циклы `for-each` для обхода массива `hours`).

**Какой метод содержит ключевое бизнес-правило?**
Метод `overtimeDays(int[] hours)` (и `weeklyOvertime`). Именно в них зашито правило переработки (превышение нормы в 40 часов). Мы разместили это в классе `TimesheetAnalyzer`, так как это бизнес-логика, а не UI.

**Какое изменение требования затронет минимум классов?**
Изменение нормы часов (например, на 8 часов). Достаточно изменить одну константу `NORMAL_HOURS_PER_DAY` в классе `TimesheetAnalyzer`. `SelfCheck` и другие методы трогать не придется.

**Объяснение выбора типов `int` и `double`:**
Часы (`hours`) — это целые числа, поэтому используется массив `int[]` и тип `int` для суммы. Среднее значение (`average`) может быть дробным, поэтому возвращаемый тип — `double`.
